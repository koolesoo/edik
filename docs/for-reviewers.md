# Руководство для проверяющих (ВКР)

Документ описывает веб-приложение **«Статистика РПЛ»**: из чего состоит репозиторий, как запустить проект локально, какие переменные окружения нужны и как устроена подача данных. Рассчитан на проверяющих, которым нужно воспроизвести работу системы без знакомства с историей разработки.

## 1. Назначение

Система предоставляет пользователю в браузере:

- список матчей Российской Премьер-Лиги (в том числе в режиме, близком к live);
- турнирную таблицу;
- экран детальной статистики выбранного матча;
- профиль с любимой командой и обзором матчей;
- регистрацию и вход (при включённой серверной базе данных).

Данные о матчах, таблице и серверной статистике матча поступают через **Flask-прокси** из внешнего **LiveScore API** (ключ и секрет задаются в окружении). Фронтенд обращается только к своему origin и пути `/api`, чтобы не раскрывать секреты в браузере и не упираться в CORS.

## 2. Структура репозитория

| Путь | Содержание |
|------|------------|
| `app.py` | Точка входа Flask: маршруты `/api/livescore/rpl/*`, регистрация blueprint авторизации. |
| `livescore_api.py` | Логика запросов к LiveScore, нормализация ответов под формат фронта. |
| `auth_api.py` | Эндпоинты `/api/auth/*`: PostgreSQL, JWT, пользователи (при заданных `DATABASE_URL` и `JWT_SECRET`). |
| `requirements.txt` | Зависимости Python. |
| `docker-compose.yml` | Локальная PostgreSQL 16 для разработки и проверки авторизации. |
| `.env.example` | Шаблон переменных окружения **без секретов** — копируется в `.env` вручную. |
| `football-stats/` | Клиентское SPA: **React 19**, **Vite 6**, маршрутизация, экраны, `src/services/api.js` (HTTP + кэш + дедупликация). |
| `scripts/` | Вспомогательные сценарии (curl, запуск dev по LAN). |
| `docs/` | Дополнительная документация, диаграммы, таблицы сценариев и требований к стеку. |
| `.github/workflows/` | При наличии — сценарии CI для репозитория (не обязательны для локального запуска). |

Каталоги **`node_modules/`**, **`.venv/`**, **`__pycache__/`**, **`football-stats/dist/`** в репозиторий не входят: они создаются при установке зависимостей и сборке. Их не нужно прикладывать к отчёту вручную — достаточно команд из раздела 4.

## 3. Требования к среде

| Компонент | Рекомендация |
|-----------|----------------|
| Python | 3.11+ (проверено в связке с зависимостями из `requirements.txt`). |

## 4. Запуск для проверки (минимальный сценарий)

### 4.0. Переменные окружения (что задаёт пользователь)

Файлы-шаблоны без секретов: **корень** — [`.env.example`](../.env.example), фронт — [`football-stats/.env.example`](../football-stats/.env.example). Flask при старте подхватывает корневой `.env`, `football-stats/.env`, а также `livescore.local.env` в корне или в `football-stats/` (удобно, если `.env` неудобно хранить в корне).

| Переменная | Где задаётся | Обязательность | Назначение |
|------------|----------------|-----------------|------------|
| `LIVESCORE_API_KEY` | корень `.env` (или `livescore.local.env`) | **Да**, для данных матчей/таблицы/статистики с LiveScore | Ключ API |
| `LIVESCORE_API_SECRET` | то же | **Да**, для того же | Секрет API |
| `LIVESCORE_RPL_COMPETITION_ID` | то же | Нет (по умолчанию 7) | Id турнира РПЛ у провайдера |
| `DATABASE_URL` | корень `.env` | Нет | PostgreSQL для `/api/auth/*` (регистрация, JWT, профиль на сервере) |
| `JWT_SECRET` | корень `.env` | Нет (но нужен вместе с `DATABASE_URL`, ≥16 символов) | Подпись JWT |
| `VITE_API_BASE` | `football-stats/.env` | Нет | Полный URL до `/api`, если фронт без Vite-прокси (другой хост/порт) |
| `VITE_API_PROXY_TARGET` | `football-stats/.env` | Нет | Куда Vite в dev проксирует `/api` (по умолчанию `http://127.0.0.1:5001`) |

Для сборки **Android (Capacitor)** см. комментарии в `football-stats/.env.capacitor.example`.

### 4.1. Ключи LiveScore

1. Скопируйте `.env.example` в файл **`.env`** в **корне** репозитория (или задайте те же имена в `livescore.local.env` — см. комментарии в `.env.example`).
2. Укажите `LIVESCORE_API_KEY` и `LIVESCORE_API_SECRET` (учётные данные от [live-score-api.com](https://www.live-score-api.com/)).
3. Не публикуйте `.env` в открытый репозиторий и не прикладывайте его к общедоступному архиву с отчётом.

### 4.2. Бэкенд (Flask)

Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

Сервер слушает **http://127.0.0.1:5001**. Без ключей LiveScore запросы к внешнему API завершатся ошибкой на стороне прокси (ожидаемо).

### 4.3. Фронтенд (Vite)

В отдельном терминале:

```bash
cd football-stats
npm ci
npm run dev
```

Откройте в браузере адрес, который выведет Vite (обычно **http://localhost:5173**). В `vite.config.js` настроен прокси **`/api` → `http://127.0.0.1:5001`**, поэтому фронт и бэкенд должны быть запущены одновременно.

### 4.4. Авторизация и профиль на PostgreSQL (опционально)

Если в `.env` заданы `DATABASE_URL` и `JWT_SECRET` (не короче 16 символов), поднимите БД:

```bash
docker compose up -d
```

Пример строки подключения см. в `.env.example`. Без этих переменных эндпоинты `/api/auth/*` отвечают **503**, а часть сценариев профиля может работать в упрощённом локальном режиме на стороне клиента — это описано в коде и не мешает проверке ленты матчей и таблицы при наличии ключей LiveScore.

## 5. Основные HTTP-маршруты бэкенда

| Метод и путь | Назначение |
|--------------|------------|
| `GET /api/livescore/rpl/live` | Текущие и недавние матчи РПЛ. |
| `GET /api/livescore/rpl/matches?date=YYYY-MM-DD` | Матчи за дату. |
| `GET /api/livescore/rpl/standings` | Турнирная таблица. |
| `GET /api/livescore/rpl/team-matches?team=...` | Окно матчей для команды (имя — строка запроса). |
| `GET /api/livescore/rpl/match-stats?match_id=...` | Массив показателей статистики матча от провайдера. |
| `POST/GET ...` под префиксом `/api/auth/` | Регистрация, вход, профиль — при настроенной БД. |

Точные имена методов см. в `auth_api.py`.

## 6. Статистика матча: источник данных

1. **Основной режим:** при известном идентификаторе матча у провайдера фронт запрашивает `/api/livescore/rpl/match-stats` и отображает полученные показатели.
2. **Если ответ провайдера не содержит строк статистики** (пустой массив при успешном HTTP), интерфейс показывает **расчётные показатели на клиенте**, согласованные с контекстом встречи (команды, время), чтобы сохранить целостность экрана и шкал. На экране выводится поясняющее сообщение пользователю.
3. Для **локальных административных матчей** предусмотрен ввод статистики через отдельный сценарий в приложении (см. разделы админки во фронте).

Таким образом, приоритет всегда у данных провайдера; клиентский расчёт используется только при отсутствии пригодных данных в ответе API.

## 7. Экономия запросов к внешнему API

У провайдера действует **дневной лимит** запросов. В проекте приняты меры: кэш с TTL, объединение параллельных одинаковых запросов (in-flight), единая точка вызовов в `football-stats/src/services/api.js`. Подробности: [`docs/minimize-api-requests.md`](minimize-api-requests.md).

## 9. Что не следует включать в архив для комиссии

- `node_modules/`, `.venv/`, `__pycache__/`, `football-stats/dist/`, кэш `.vite/`;
- файлы `.env` с реальными ключами и паролями БД;
- локальные `livescore.local.env` с секретами;
- каталоги IDE (`.idea/`, личные настройки `.vscode/`) — по желанию; в репозитории они в `.gitignore`.

Достаточно исходного кода, `package-lock.json`, `requirements.txt`, `.env.example` и данного руководства.

## 10. Контрольный чеклист проверяющего

1. Скопирован `.env` из `.env.example`, заполнены ключи LiveScore.
2. Выполнен `pip install -r requirements.txt`, запущен `python app.py` (порт 5001).
3. В `football-stats` выполнены `npm ci` и `npm run dev`.
4. Открыта главная страница: видны матчи или сообщение об ошибке сети/ключей (при неверных ключах — разобрать ответ в консоли браузера или логах Flask).
5. Открыта таблица и экран статистики матча для матча с известным id.
6. (Опционально) Запущен `docker compose`, в `.env` указаны `DATABASE_URL` и `JWT_SECRET` — проверена регистрация/вход.

При несоответствии версий Python/Node ориентируйтесь на раздел 3 (Node 20 LTS, Python 3.11+).
