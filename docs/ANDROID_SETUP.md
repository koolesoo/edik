# Запуск Android-сборки на другом компьютере (Android Studio + APK)

Инструкция для человека, который **первый раз** открывает проект и хочет **собрать приложение и проверить его на устройстве или эмуляторе**.

Проект: веб-клиент **React + Vite** в каталоге `football-stats/`, обёртка **Capacitor**, нативный проект — `football-stats/android/`. Бэкенд **Flask** в корне репозитория (`app.py`) нужен, если проверяете работу API с телефона, а не только установку APK.

---

## 1. Что установить на новый компьютер

### 1.1. Android Studio

1. Скачайте [Android Studio](https://developer.android.com/studio) с официального сайта и установите.
2. При первом запуске выберите стандартную установку (**Standard**), чтобы подтянулись **Android SDK**, **Android SDK Platform** и инструменты сборки.
3. В **Settings → Appearance & Behavior → System Settings → Android SDK** убедитесь, что установлен хотя бы один **API Level** (например 34 или 35) и **Android SDK Build-Tools**.

После этого студия сама создаст файл `football-stats/android/local.properties` с путём к SDK при первой сборке (его не нужно копировать с другого ПК).

### 1.2. Node.js

1. Установите **LTS-версию Node.js** с [nodejs.org](https://nodejs.org/) (вместе с ней ставится **npm**).
2. В терминале проверьте:

```bash
node -v
npm -v
```

### 1.3. Git (если код берёте из репозитория)

Установите [Git](https://git-scm.com/) и склонируйте проект:

```bash
git clone <URL-вашего-репозитория>
cd footstat-main
```

Если проект передали **архивом (ZIP)** — распакуйте в любую папку и работайте из корня распакованного каталога (ниже он считается **корнем проекта**).

## 2. Структура, которая важна для Android

| Путь | Назначение |
|------|------------|
| `football-stats/` | Фронтенд и скрипты npm |
| `football-stats/android/` | Проект Gradle для открытия в Android Studio |
| `football-stats/.env.capacitor.example` | Шаблон переменных для сборки под APK |
| `app.py`, `requirements.txt` | Бэкенд Flask (опционально для локальной проверки API) |

Папки **`football-stats/node_modules`** и **`football-stats/dist`** не обязательно переносить — их восстановят команды ниже.

## 3. Установка зависимостей фронтенда

В терминале:

```bash
cd путь/к/репозиторию/football-stats
npm install
```

Дождитесь окончания без ошибок. Если есть ошибки с доступом к сети или правами — исправьте их прежде чем продолжать.

## 4. Адрес API для приложения (`VITE_API_BASE`)

В APK **нет** прокси Vite как в браузере при `npm run dev`. Поэтому при сборке в код «зашивается» полный URL бэкенда через переменную **`VITE_API_BASE`** (до суффикса `/api`, в том же виде, что в `.env.capacitor.example`).

### Вариант A: Бэкенд уже в интернете (HTTPS)

1. Скопируйте файл-пример:

```bash
cd football-stats
cp .env.capacitor.example .env.capacitor
```

2. Отредактируйте `.env.capacitor` и укажите реальный URL, например:

```env
VITE_API_BASE=https://example.com/api
```

Обязательно **HTTPS** для типичной **release**-сборки.

### Вариант B: Бэкенд на этом же компьютере, проверка с физического телефона в Wi‑Fi

1. Узнайте **локальный IP** компьютера в сети (например `192.168.1.10`).
2. Запустите Flask из корня проекта (`python app.py`). В этом репозитории в `app.py` уже указано **`host="0.0.0.0"`** и порт **5001**, то есть доступ из LAN возможен, если firewall пропускает порт.
3. В `.env.capacitor`:

```env
VITE_API_BASE=http://192.168.1.10:5001/api
```

**Важно:** HTTP разрешён в проекте только для **debug**-сборки Android (см. `android/app/src/debug/`). Для установки из Android Studio кнопкой **Run** обычно собирается **debug** — этого достаточно для проверки по HTTP в LAN.

### Вариант C: Эмулятор Android, Flask на том же ПК

Часто используют специальный адрес эмулятора к хосту:

```env
VITE_API_BASE=http://10.0.2.2:5001/api
```

Порт **5001** — ориентир из типичного запуска проекта; если у вас другой порт, подставьте свой.

## 5. Сборка веб-части и копирование в проект Android

Из каталога **`football-stats`**:

```bash
npm run android:sync
```

Эта команда:

1. Выполняет `vite build --mode capacitor` (подхватит `football-stats/.env.capacitor`, если файл есть).
2. Копирует результат в `android/app/src/main/assets/public` через Capacitor.

Если **нет** файла `.env.capacitor`, можно один раз передать переменную в командной строке (macOS/Linux):

```bash
VITE_API_BASE=https://ваш-домен.example/api npm run android:sync
```

В Windows (cmd):

```cmd
set VITE_API_BASE=https://ваш-домен.example/api && npm run android:sync
```

После **каждого** изменения кода фронтенда перед проверкой в студии снова выполните **`npm run android:sync`**.

## 6. Открытие в Android Studio

1. Запустите **Android Studio**.
2. **File → Open** и выберите папку **`football-stats/android`** внутри репозитория (именно её, не весь монорепозиторий целиком — так надёжнее для Gradle).
3. Дождитесь **Gradle Sync**. Если спросят про доверие к проекту — подтвердите.
4. Если сверху нет запускаемого модуля **app**, выберите конфигурацию **app** в выпадающем списке.

---

## 7. Устройство для запуска

### Физический телефон

1. На телефоне: **Настройки → Для разработчиков → Отладка по USB** (включить).
2. Подключите USB, на телефоне разрешите отладку для этого компьютера.
3. В Android Studio в списке устройств выберите ваш телефон.

### Эмулятор

1. **Tools → Device Manager → Create Device**, выберите модель и образ системы, завершите мастер.
2. Запустите эмулятор и выберите его как цель запуска.

---

## 8. Запуск и получение APK

### Быстрая проверка через Run

Нажмите зелёную кнопку **Run** (▶). Студия соберёт **debug** и установит приложение на выбранное устройство.

### Готовый APK-файл (debug)

В терминале из каталога **`football-stats/android`**:

- **Linux/macOS:**

```bash
./gradlew assembleDebug
```

- **Windows:**

```cmd
gradlew.bat assembleDebug
```

Файл APK обычно здесь:

`football-stats/android/app/build/outputs/apk/debug/app-debug.apk`

(точное имя файла смотрите в папке `debug/`.)

Этот файл можно скопировать на телефон и открыть для установки (может потребоваться разрешение установки из неизвестных источников).

### Release и Google Play

Для подписанного **release** нужны **keystore** и файл **`android/keystore.properties`** по образцу **`android/keystore.properties.example`**. Это отдельная настройка под публикацию; для **проверки работы** достаточно **debug**.

## 9. Локальный бэкенд Flask (если нужен живой API)

Только если решили проверять не статический интерфейс, а загрузку данных с вашего сервера:

1. В корне проекта (рядом с `app.py`):

```bash
python3 -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt
```

2. По инструкции владельца проекта создайте **`.env`** с `LIVESCORE_API_KEY` и `LIVESCORE_API_SECRET` (см. корневой `.env.example`).

3. Запуск сервера — как принято в команде (часто `python app.py`), убедитесь, что порт совпадает с **`VITE_API_BASE`**.

Без работающего API приложение может открываться, но списки матчей и ошибки сети будут ожидаемы.

## 10. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| Gradle: Java не найден | В Android Studio: **Settings → Build … → Gradle → Gradle JDK** — выберите встроенный JDK студии. |
| Нет SDK | Откройте SDK Manager в студии и доустановите платформу и build-tools. |
| Приложение установилось, но «нет связи с сервером» | Пересобрали ли **`npm run android:sync`** после смены `VITE_API_BASE`? Правильный ли URL с телефона/эмулятора? Работает ли Flask и firewall? |
| HTTP к API не работает в release | В проекте cleartext для HTTP включён для **debug**. Для **release** нужен **HTTPS**. |
| После `git pull` пропал интерфейс в приложении | Снова выполните **`npm run android:sync`** и пересоберите в студии. |

---

## 11. Краткий чеклист исполнителя

1. Установить **Android Studio** и **Node.js LTS**.
2. Получить код (**git clone** или распаковать архив).
3. `cd football-stats && npm install`
4. Создать **`football-stats/.env.capacitor`** с верным **`VITE_API_BASE`**.
5. `npm run android:sync`
6. Открыть **`football-stats/android`** в Android Studio → **Run** или **`assembleDebug`**.
7. При смене фронта или URL API — повторить шаги 4–6 по необходимости.

Если что-то из списка отличается в вашей команде (порт Flask, имя ветки, обязательный VPN), добавьте это в конец этого файла своими пометками.
